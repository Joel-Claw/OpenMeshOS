## Development Work

### MeshBoard/MeshClock Migration (TDeckBoard/TDeckClock replacement)
**Status: Complete — committed and pushed to dev**

#### Problem
TDeckBoard and TDeckClock were T-Deck-specific implementations of MeshCore's MainBoard and RTCClock interfaces. They hardcoded ESP32-only APIs (esp_system.h, ESP.restart(), temperatureRead()) and T-Deck-specific ADC pins. With the IBoard hardware abstraction layer already in place, these classes needed to be platform-agnostic to support Heltec V3 and RAK4631.

#### Solution
Created generic MeshBoard and MeshClock classes that delegate to the IBoard hardware abstraction:

1. **MeshBoard** (replaces TDeckBoard) — Implements mesh::MainBoard, delegates battery voltage, MCU temp, reboot, and reset reason to IBoard::batteryMilliVolts(), mcuTemperature(), reboot(), resetReason(). Manufacturer name comes from IBoard::boardName(). ADC multiplier is still tracked locally (settable via setAdcMultiplier()).

2. **MeshClock** (replaces TDeckClock) — Implements mesh::RTCClock, uses millis() as drift baseline. Time sync from GPS (onGpsTime), NTP (onNtpTime), or BLE companion (onBleTime). Platform-agnostic, works on any Arduino-capable platform.

3. **MeshService** updated to use MeshBoard/MeshClock instead of TDeckBoard/TDeckClock.

4. **Removed**: TDeckBoard.h/cpp and TDeckClock.h/cpp (no longer referenced by any code).
