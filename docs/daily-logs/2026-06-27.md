## Development Work

### CI Fix: fail-fast and WIP Platform Handling
**Status: Fixed — all ESP32 builds now pass, RAK4631 marked as WIP**

#### Problem
The CI build matrix had `fail-fast: true` (GitHub Actions default), which meant when the rak-wisblock build failed (expected for WIP nRF52 platform), GitHub Actions cancelled all other in-progress builds. This left t-deck and t-deck-plus builds perpetually cancelled during LVGL compilation, masking whether they actually passed.

Additionally, the "Check firmware size" step failed for rak-wisblock because no firmware binary was produced (build failed), and the step had no `continue-on-error` guard.

#### Fix
1. **`fail-fast: false`** added to strategy — all matrix jobs now run to completion independently
2. **`continue-on-error: ${{ matrix.continue-on-error }}`** added to "Check firmware size" and "Build merged binary" steps — WIP platforms gracefully skip these steps
3. **Warning instead of error** for missing firmware binary on WIP platforms

### RAK4631 Build Fix: Suppress MeshCore class-memaccess Warning
**Status: Fixed — nRF52 build now passes compilation**

#### Problem
The ARM GCC toolchain (gccarmnoneeabi) for nRF52840 treats `-Wclass-memaccess` as an error when `memset` is used on non-trivial types. MeshCore's `ClientACL.cpp` (line 114) uses `memset(c, 0, sizeof(*c))` on a `ClientInfo` struct, which triggers this error. Since MeshCore is a git submodule, we can't modify the source.

#### Fix
Added `-Wno-error=class-memaccess` to the rak-wisblock build flags in `platformio.ini`.
