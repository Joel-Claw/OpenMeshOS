## Development Work

### CI Fix: Remove restore-keys Fallback (3276eaa)

The July 18 cache key fix was incomplete. The cache key now included the MeshCore submodule hash, but `restore-keys` fallback still matched cache entries WITHOUT the submodule hash. This restored stale `.o` files from the old MeshCore version, causing the same `P_LORA_DIO_1 not declared in this scope` error.

**Root cause**: `restore-keys` allows partial key matching. Without the submodule hash in the fallback key, old cache entries from before the submodule bump were restored, including `ESP32Board.cpp.o` compiled from old MeshCore (without `P_LORA_DIO_1` define).

**Fix (3276eaa)**: Removed `restore-keys` from all three workflows (ci.yml, codeql.yml, release.yml). Without restore-keys, a cache miss on the exact key results in a fresh build, which is the correct behavior after a submodule bump. Also added `P_LORA_DIO_1` and `LORA_*` defines to all three ESP32 environments in `platformio.ini` (required by MeshCore 1.16.0+).
