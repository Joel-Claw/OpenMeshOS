## Development Work

### Memory Audit Recommendations #6 and #8

Implemented two remaining memory audit recommendations:

**#6: Pre-allocate tone buffer (Notification)**
- `Notification::init()` now pre-allocates the tone buffer (3200 bytes = 1600 × int16_t) via `heap_caps_malloc(MALLOC_CAP_8BIT)` once at boot
- `playToneCustom()` and `playPattern()` use the pre-allocated buffer instead of allocating/freeing per call
- Eliminates the only per-event heap allocation in the firmware
- Falls back to per-call malloc if pre-allocation fails (graceful degradation)
- `_toneBuf` pointer is safe for non-audio platforms (heltec-v3) — stays `nullptr`, never dereferenced

**#8: Heap watchdog emergency reboot (HeapMonitor)**
- When `freeHeap()` drops below `criticalHeapBytes` threshold:
  - Logs CRITICAL message with stack high-water marks
  - Waits 500ms for log flush
  - Calls `ESP.restart()` to force a clean reboot
- Adds a WARNING log for the warn-level threshold (no reboot, just visible in logs)
- This is the last line of defense against undiscovered memory leaks that could cause undefined behaviour
- Thresholds remain configurable per platform (ESP32: 15KB critical, nRF52: 4KB critical)
