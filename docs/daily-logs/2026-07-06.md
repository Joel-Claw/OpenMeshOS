## Development Work

### BLE OTA Abort Timeout (Security Audit Recommendation #5)
Implemented the 5th recommendation from the security audit: BLE OTA abort timeout.

**Problem**: If a companion app started an OTA firmware update but then disconnected or stopped sending data (crash, BLE drop, user walked away), the ESP32 Update library would stay open indefinitely, blocking future OTA attempts and keeping flash write resources allocated.

**Solution**: Added a 30-second timeout in `BLECompanionESP32::tick()`:
- `_otaLastDataMs` tracks the timestamp of the last OTA data packet
- Updated on OTA start and on each data write in `handleFirmwareWrite()`
- In `tick()`, if `_otaInProgress` and `(now - _otaLastDataMs) >= OTA_TIMEOUT_MS`, auto-abort
- Calls `Update.abort()`, resets all OTA state, notifies companion app with step=0xFF
- 30s is generous enough for BLE reconnection delays but short enough to not hang indefinitely
