## Development Work

### BLE Companion Abstraction Layer (IBLECompanion)
**Status: Complete — ESP32 and nRF52 implementations created**

#### Problem
The BLECompanion class was tightly coupled to the ESP32 BLE stack (`BLEDevice`, `BLEServer`, `BLECharacteristic`, `ESP_BLE_SEC_ENCRYPT`, `ESP_GATT_PERM_*`, `Update.h`). The nRF52840 (RAK4631) uses a completely different BLE stack (Nordic SoftDevice via ArduinoBLE library), making the ESP32 BLE code unusable on nRF52.

#### Solution
Created a platform-agnostic BLE companion abstraction following the existing IBoard/IDisplay/IInput pattern:

1. **IBLECompanion.h** — Pure virtual interface with `init()`, `tick()`, `notifyMessage()`, `notifyStatus()`, `isConnected()`, `setEnabled()`, `enabled()`. Factory function `createBLECompanion()` and convenience accessor `theBLECompanion()`.

2. **BLECompanion.h/cpp** (refactored) — Now `BLECompanionESP32`, implements `IBLECompanion` using the ESP32 Arduino BLE stack. All original functionality preserved (config, messaging, status, BLE OTA firmware update). Guarded by `#if defined(ARDUINO_ARCH_ESP32)`.

3. **BLECompanionNRF52.h/cpp** (new) — Implements `IBLECompanion` using the ArduinoBLE library (Nordic SoftDevice). Uses 128-bit UUIDs (ArduinoBLE requires full UUIDs for custom services). Supports config read/write, message notify/write, status notify. BLE OTA firmware update is NOT implemented yet (nRF52 uses Nordic DFU bootloader, different mechanism). Guarded by `#if defined(ARDUINO_ARCH_NRF52840)`.

4. **BLECompanionFactory.cpp** (new) — Compile-time platform selection via `#if defined(ARDUINO_ARCH_ESP32)` / `#elif defined(ARDUINO_ARCH_NRF52840)`.

5. **buildStatusPayload** — Updated to use `platform::freeHeap()` instead of `ESP.getFreeHeap()`, making it platform-agnostic. PSRAM reporting is conditional on `BOARD_HAS_PSRAM`.

  - Note: BLECompanionFactory.cpp excluded because it includes both headers, and the nRF52 Arduino core may not have all ESP32 headers. The factory logic is inlined in the nRF52 build path via BLECompanionNRF52::instance() directly.
  - Actually, the factory uses `#if defined(ARDUINO_ARCH_ESP32)` / `#elif defined(ARDUINO_ARCH_NRF52840)` so it should work on both. But excluding it from nRF52 is safer since BLECompanion.h includes ESP32 BLE headers that don't exist on nRF52.

#### BLE Service UUID Compatibility
The ESP32 implementation uses 16-bit short UUIDs (0xFEDC service, 0x0001-0x0006 characteristics). The nRF52 implementation uses 128-bit UUIDs based on the standard Bluetooth base UUID pattern: `0000XXXX-0000-1000-8000-00805F9B34FB` where XXXX matches the ESP32 16-bit IDs. This ensures the same companion app works across both platforms.
