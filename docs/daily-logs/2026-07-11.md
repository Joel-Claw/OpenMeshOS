## Development Work

### RAK4631/nRF52 Platform Port — Build Fixes

Completed the nRF52/RAK4631 platform port that was in progress. All changes build successfully on both rak-wisblock and heltec-v3 targets.

**Key changes:**

1. **SPIFFS compatibility shim** (`boards/SPIFFS.h`):
   - Wraps Adafruit InternalFS (LittleFS) with a SPIFFS-compatible API
   - All existing `SPIFFS.begin()`, `SPIFFS.open()`, `SPIFFS.exists()` calls work unchanged
   - Provides `raw()` accessor for MeshCore's IdentityStore which needs the underlying InternalFS

2. **Platform-agnostic filesystem types** (`src/mesh/FSInterface.h`):
   - `oms_fs::FS` type alias (fs::FS on ESP32, SPIFFSCompat on nRF52)
   - `oms_fs::File` type alias for file handles

3. **Heap monitoring fixes** (PlatformCompat, HeapMonitor):
   - Replaced `xPortGetFreeHeapSize()` with sbrk-based heap estimation (FreeRTOS heap_3 doesn't implement it)
   - Conditional FreeRTOS includes (nRF52 Arduino core has FreeRTOS built in)
   - `ESP.restart()` → `NVIC_SystemReset()` on nRF52
   - Skip `xTaskGetHandle()` on nRF52 (INCLUDE_xTaskGetHandle=0)

4. **Watchdog fix**: C++14-compatible static local instead of `inline static` (nRF52 toolchain)

5. **Trackball fix**: `uint32_t` instead of `gpio_num_t` on nRF52 (no gpio_num_t type)

6. **BoardRAK4631 fixes**:
   - `SPI.begin()` takes no arguments on nRF52 (pins from variant.h)
   - Renamed `LED_BLUE`/`LED_GREEN` to `LED_BLUE_PIN`/`LED_GREEN_PIN` (avoids variant.h macro clash)
   - Fixed `NRF_GPIO_PIN_SELOW` → `NRF_GPIO_PIN_SENSE_LOW`

7. **DisplaySSD1306 fix**: `Wire.begin()` takes no pin args on nRF52

8. **BLECompanionNRF52 fix**: `configUuid128Len` → `configUuid128Count` (correct API name)

9. **MeshService fix**: Use default SPI on nRF52 (only one SPI bus, no HSPI/VSPI split)

10. **OpenMeshChat fix**: Use `oms_fs::FS` type, IdentityStore gets `raw()` InternalFS on nRF52

11. **time.h shim fix**: Use `#include_next <time.h>` with sys/select.h guard instead of our own `time_t` typedef

12. **Main.cpp**: Guard T-Deck-only includes for nRF52, use `oms::Watchdog` namespace
