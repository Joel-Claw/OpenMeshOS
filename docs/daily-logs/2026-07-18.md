## Development Work

### CI Fix: Cache Key + Action Version Bumps

The July 17 MeshCore submodule bump (9668c8f) exposed a CI cache issue: the PlatformIO cache key only included `platformio.ini` hash, not the MeshCore submodule commit hash. When the submodule pointer changed, CI reused stale compiled objects from the old MeshCore version, causing a `P_LORA_DIO_1 not declared in this scope` build error.

**Fix (eac98da)**: Added MeshCore submodule commit hash to cache key across all three workflows (ci.yml, codeql.yml, release.yml). Also bumped GitHub Actions versions:
- `actions/checkout` v4 -> v5 (Node 20 deprecation)
- `actions/cache` v4 -> v5
- `actions/upload-artifact` v4 -> v5

**Fix (d2bfc5a)**: Same cache key fix applied to release workflow. Added WTFPL license header to `src/version.h` (was flagged by lint job). Bumped `actions/cache`, `upload-artifact`, `download-artifact` to v5.
